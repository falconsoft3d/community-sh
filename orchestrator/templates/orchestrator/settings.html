Ayuda

Guías e instrucciones para configurar la plataforma

{% include "orchestrator/includes/github_icon.html" with cls="h-4 w-4" %} Cómo obtener un GitHub Personal Access Token

  1. Ve a GitHub Settings → Developer settings → Personal access tokens
  2. Haz clic en "Generate new token" (classic)
  3. Dale un nombre descriptivo (ej: "Community SH")
  4. Selecciona los siguientes permisos:
    • repo - Acceso completo a repositorios privados
    • read:org - Leer información de organizaciones (opcional)
  5. Haz clic en "Generate token"
  6. Copia el token y pégalo en la pestaña GitHub (guárdalo en un lugar seguro, no podrás verlo de nuevo)

Configurar SSL con Let's Encrypt

  1. Asegúrate de que tu dominio esté apuntando a la IP de este servidor
  2. Verifica que el puerto 80 esté disponible y accesible desde internet
  3. Ve a la pestaña "Domain & SSL"
  4. Ingresa tu dominio principal
  5. Haz clic en "Generar Certificado SSL"
  6. Completa el formulario con tu dominio y email
  7. El sistema generará automáticamente el certificado y lo configurará
  8. Los certificados se renovarán automáticamente antes de expirar

Consejos generales

  • Guarda siempre los cambios después de modificar cualquier configuración
  • Mantén tu GitHub Personal Access Token seguro y no lo compartas
  • Si cambias el dominio principal, actualiza también tus registros DNS
  • El registro de usuarios puede deshabilitarse temporalmente durante mantenimiento
  • Revisa regularmente la pestaña "Acerca de" para conocer nuevas características

API REST

Administra proyectos, instancias, backups, tareas y Todo desde tus scripts o integraciones. Cada llamada usa los permisos del usuario del token.

URL base

{{ api_url }}

Autenticación

Cabecera Authorization: Bearer TU_TOKEN con un token personal. Son los mismos tokens que el servidor MCP: créalos o revócalos en la pestaña .

Ejemplo

curl -H "Authorization: Bearer TU_TOKEN" {{ api_url }}instances/

curl -X POST -H "Authorization: Bearer TU_TOKEN" {{ api_url }}instances/12/backup/
# → {"task_id": 345, "status": "pending"}

curl -H "Authorization: Bearer TU_TOKEN" {{ api_url }}tasks/345/
MétodoRutaQué hace
GET/api/projects/Proyectos que puedes ver
POST/api/projects/Crear proyecto (name, description)
GET/api/instances/Instancias (estado, versión, proyecto, URL)
POST/api/instances/Crear instancia (name, odoo_version, project); despliega con /deploy/
POST/api/instances/{id}/deploy/Desplegar (devuelve task_id)
POST/api/instances/{id}/restart/Reiniciar
POST/api/instances/{id}/stop/Detener
POST/api/instances/{id}/backup/Crear backup (include_filestore)
POST/api/instances/{id}/duplicate/Duplicar (new_name)
DELETE/api/instances/{id}/Eliminar instancia
GET/api/backups/?instance=nombreBackups
GET/api/backups/{id}/download/Descargar ZIP
POST/api/backups/{id}/restore/Restaurar en su instancia
GET/api/tasks/{id}/Estado de una tarea en segundo plano
GET/POST/api/todos/Tareas del menú Todo
PATCH/api/todos/{id}/Cambiar estado (status, completion_note)

Las operaciones largas (desplegar, backup, restaurar, duplicar) devuelven task_id: consulta /api/tasks/{id}/ hasta que status sea done o failed. Abre {{ api_url }} con sesión iniciada para la API navegable.

Claude Desktop: añade esto a claude_desktop_config.json (usa el puente mcp-remote, requiere Node.js) y reinicia Claude:

  "mcpServers": {
    "community-sh": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "{{ mcp_url }}", "--header", "Authorization: Bearer TU_TOKEN"]
    }
  }
}

El panel debe ser accesible desde donde corre Claude; usa HTTPS si es por Internet, porque el token viaja en cada petición.
